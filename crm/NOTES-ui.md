# CRM UI · заметки для сервера и QA

Файлы: `crm/index.html`, `crm/crm.css`, `crm/crm.js` (чистый JS, маршруты по hash).
Демо без сервера: `/crm/?demo=1&as=paid|trial|candidate|owner|login|key`. Внизу справа переключатель ролей. Данные вымышленные, права в демо повторяют контракт (сетевое представление, 404 на чужую карточку для кандидата, owner-only маршруты).

## Маршруты интерфейса
`#/clients` `#/new` `#/c/<id>[/profile|match|notes|plans|history|dictate|review|ai|offer?r=<rid>]` `#/plans` `#/requests` `#/portfolio` `#/tariff` `#/notify` `#/demand` (кандидат) · владелец: `#/inbox[/<rid>]` `#/partners` `#/reviews` `#/archive` `#/audit`.

## Сверка с сервером (api/crm.mjs, NOTES-backend.md)
Слой `api()` в реальном режиме проходит через `adapt()` в crm.js: он приводит ответы сервера к форме, с которой работают экраны (`{rows}`, `{notes}`, `{tasks}`, `{audit}`, `{partners}`, `{rqs}`, `{rq}`, `{portfolios}`, `{demand}`, места по направлениям, `pay1:{at,amount}`, `conflict:{current}`, сообщения `from:'partner'|'orbiq'` с `attachIds`).
Проверено сквозным прогоном в Playwright на локальном сервере (`api/crm.mjs` + `tests/kvmock.mjs`): вход владельца по ссылке и ключу, приглашение двух партнеров, платеж 1 и проба, карточка, запрос, публичная формулировка, диктовка → очистка → разбор → сохранение, подборка, заметка, задача, iCal, «Все», сетевая карточка, обращение, заметка → Orbiq, пересылка владельцем, засчитать знакомство, архив, журнал. Ошибок API (4xx/5xx) и JS нет.
Использованы маршруты сверх контракта: `demand`, `pf/all`, `pf/extend`, `owner/write` (кнопка «Написать партнеру» в карточке у владельца), `intro/use` (кнопка во «Входящих»), `rq/att` (скачивание вложения), `tg/link`, `tg/off`, `tg/events`.
Учтено: `me.needKey` → экран ключа; `?login=expired|suspended` и `?invite=used|revoked|expired|invalid` → сообщение на экране входа; срок задачи уходит как `ГГГГ-ММ-ДДTЧЧ:ММ`; ячейка удаляется через `null`; `question/mark` только `asked|later|done`, ответ «да» по уточнению создает задачу на поиск; решения проверки `yes|no|insufficient`; вложения до 700 КБ; `invite/create` с `confirm10m`; у владельца нет раздела «Планы» (сервер не дает `tasks`).
Не сделано в UI: `note/edit`, `client/link`, `client/primary`, редактор каталога (`catalog/*`), `invite/revoke`.

## Поведение, важное для QA
- Текст диктовки и MD проходят локальную подсветку (почта, телефон, ссылка, организация, имена; одиночные имена с заглавной не отмечены по умолчанию). Отмеченное заменяется на `[скрыто]` до `client/extract`. Исходный текст хранится только в `sessionStorage` черновика диктовки и удаляется после разбора.
- Диктовка: `webkitSpeechRecognition` включается только после галочки «Понимаю» с предупреждением про облачное распознавание. Без API показывается подсказка про микрофон клавиатуры. Аудио не пишется.
- Публичная формулировка запроса: до подтверждения сеть видит только категорию; подтверждение блокируется, если в тексте найдены контакты.
- Возраст из таблицы автоматически заполняет ячейку `about.age` (fact).
- Владелец Orbiq открывает чужие карточки только на просмотр, без диктовки, импорта и архива.
- Пересылка во «Входящих»: чекбоксы «Предложение / Условия / вложение» собирают текст, поле предупреждает о контактах.
- Текст задания §4 вставлен дословно, «ё» заменена на «е» по правилу интерфейса.
