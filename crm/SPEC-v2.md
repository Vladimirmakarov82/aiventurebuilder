# Orbiq CRM · изменения v2 (решения Владимира 23.11.2026)

Контракт v1 (CONTRACT.md) действует, кроме пунктов ниже. Буквы «ё» нет. Хранение: никаких фамилий, почт и телефонов клиентов (как и раньше). Почты партнеров — только для входа.

## 1. Клиенты Orbiq (кабинет владельца)
- Владелец (owner, mfa) ведет собственную CRM: создает, дополняет текстом, правит, архивирует карточки. Владелец карточки = специальный id `orbiq`. В таблице и в сетевом виде метка «Клиент Orbiq».
- Для партнеров такие карточки видны в сети как обычные, со значком «Ведет Orbiq» (вместо скрытого партнера). Обращения по ним идут владельцу так же, как все.
- В кабинете владельца раздел «Мои клиенты» (клиенты Orbiq) первым пунктом меню, затем «Входящие», «Партнеры», «Каталог»…

## 2. Готовность карточки = 6 блоков (заменяет 15/18 для зачета и процент в списке)
1. Возраст и семья.
2. Капитал диапазоном и откуда оценка.
3. На чем заработал: отрасль, масштаб, роль в компании.
4. Интересы с конкретикой.
5. Подтвержденный запрос или потребность.
6. Сколько лет знакомы и является ли клиентом партнера (платил ли деньги партнеру): `relation.years` (число), `relation.isClient` (yes|no|unknown).
Готовность = заполненные блоки / 6, «готова» при 6/6 (85%+ ≈ 6 из 6 или 5 из 6 с блоком 5 обязательным — правило: готова, если есть блоки 2, 3, 5, 6 и всего ≥5). Круг 360° остается как детали. `missing` из intake/extract возвращает недостающие блоки с вопросом. Rules-парсер: «знакомы 8 лет», «лет 10 знаем друг друга», «работаем с 2018» → years; «наш клиент», «покупал у нас», «платил за …» → isClient=yes.

## 3. Профиль продукта партнера
- `partner/invite` принимает `productText` (свободный текст: сайт, переписка, заметки). ИИ (или эвристика) строит `product`: {summary, whoNeeds, fitSignals:[...], categories:[...], typicalEarnPerClient:{min,max,currency:'USD'}}. Владелец видит и правит перед отправкой приглашения (`partner/product` {pid, product}). Партнер видит карточку своего продукта в кабинете («Ваш продукт в сети») и может предложить правку через Orbiq.
- Роль при приглашении: `kind: 'supplier' | 'networker'` (см. §5).

## 4. Подборка-досье под продукт партнера
- `fit/list` (партнер) → `{total, potential:{min,max}, rows:[{cid, alias, age, capital, dossier, whyFit, potential:{min,max}, hasRequest:bool, leadBy: 'Orbiq'|'партнер по <сфере>'}]}`. `dossier` — 2–4 предложения обезличенного описания из подтвержденных фактов карточки: отрасль, масштаб диапазоном, роль, регион укрупненно («юг России»), интересы. Ни имен компаний, ни городов, ни точных сумм, ни контактов. `whyFit` — связь с fitSignals продукта. Строится из сетевых карточек + профиля продукта (ИИ, кеш по карточке+продукту; без ИИ — эвристика по категориям и интересам).
- Видно всем партнерам (включая базовых) без кнопок, кроме «Предложить через Orbiq» с учетом лимита (§5).
- Наверху итог: «N клиентов, потенциал $X–Y в год».

## 5. Статусы и лимиты (заменяет пробу «3 знакомства за 30 карточек»)
- `new` — приглашен. Видит свою CRM, карточку продукта, подборку `fit/list` (досье без действий) и задачу: занести 50 готовых карточек.
- `basic` — после 50 готовых карточек (сервер считает, владелец подтверждает выборочной проверкой как раньше: выборка из каждой 20 + остаток). Права: `rq/create` не чаще 1 раза в календарный месяц (по UTC+3), видит сферу партнера, ведущего клиента. Входящие предложения сети для его клиентов (продукты других партнеров под запросы его клиентов) — без лимита.
- `paid` («Партнер Orbiq», $20 000/год): обращения без лимита, первым видит новые запросы своей категории (бесплатные видят их через 72 часа), упаковка продукта, 20 семейных приглашений, места ≤2 на категорию (`seat/list` → счетчик «занято N из 2» показывать базовым).
- `networker` (отдельная роль, задается только владельцем при приглашении; у нетворкера нет своего продукта): заносит базу, видит сеть и запросы, может передать своего клиента под продукт сети (`rq/create` с `kind:'refer'`, без лимита) и получает вознаграждение за приведенного клиента по договоренности; не может предлагать свой продукт (нет профиля продукта), не может купить место поставщика, не получает статус «Партнер Orbiq» и семейные приглашения. Чтобы поставщик не «ушел в нетворкеры»: роль меняет только владелец; при наличии product у партнера роль networker недоступна.
- Комиссия одинаковая для всех ролей, согласуется по направлению вручную (как в v1).
- Удалить из интерфейса и API квоту знакомств «3 за 30 карточек»; `pf/*` переиспользовать для проверки 50 карточек.

## 6. Тексты
- Онбординг-ролик и экран «Новый»: «Поздравляем, вы в сети Orbiq», карточка продукта, подборка-досье с потенциалом, задача «50 готовых карточек → статус базового партнера», счетчик мест в категории.
- Формулировки в кабинете: «Клиенты остаются за вами. Другие партнеры видят их обезличенно».
