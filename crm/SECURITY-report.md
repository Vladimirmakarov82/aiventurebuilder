# Orbiq CRM · проверка безопасности

**Итог: утечек между ролями нет. Найдено 17 проблем, 15 исправлено в коде, 2 требуют решения координатора.** Все три набора тестов проходят: `crm-unit` — все, `crm-acceptance` — 118 проверок (PASS 107, FAIL 0, NOT TESTED 11), `crm-security` — 29 проверок.

- Версия: ветка `journal-editorial`, незакоммиченные `api/crm.mjs` и `api/_crm_core.mjs` на 23.11.2026.
- Методика: OWASP Authorization Cheat Sheet, OWASP ASVS (V1–V5, V7, V8, V13).
- Источники: `crm/CONTRACT.md` §6, `crm/NOTES-backend.md`, `crm/QA-report.md`, ТЗ части III–V и §9.
- Тесты безопасности: `node tests/crm-security.mjs`. Мок Redis внутри файла, как в `tests/crm-acceptance.mjs`. Контрольный прогон: откат исправлений 2, 5, 7 и 8 ломает соответствующие проверки.

## 2. Не исправлено: нужно решение координатора

1. **Высоко · `api/j.mjs` вне зоны этой проверки.** Там тот же ключ `'dev'` при пустом `SESSION_SECRET`. Ссылка отписки `sign({u})` без срока — вечная сессия журнала: `me()` проверяет только `u`. Исправить: в `me()` требовать `e` и `exp`; в ссылке отписки добавить `k:'unsub'` и проверять его в маршруте отписки.
2. **Высоко · окружение.** Превью и прод используют один Upstash Redis. Любая ошибка на превью — доступ к рабочим данным. Нужна отдельная база для превью. Пока ее нет, на превью нельзя заводить реальных людей.
3. **Средне · `/i/?t=` в адресе страницы.** Токен приглашения может уйти в заголовке `Referer` на сторонние ресурсы страницы. Добавить в `vercel.json` для `/i/` заголовок `Referrer-Policy: no-referrer`.
4. **Средне · размер вложений.** Файл до 2 МБ хранится в Redis как base64, это около 2,7 МБ. Лимит запроса Upstash зависит от тарифа, на бесплатном — 1 МБ. Большие файлы тогда дают 500. Для прода — Vercel Blob или лимит 700 КБ.

## 3. Переменные, без которых функции теперь закрыты

- `SESSION_SECRET` — без него вход и сессии не работают (503).
- `SITE_URL=https://orbiqgroup.com` — адрес в письмах и ссылках. В продакшене без него используется `orbiqgroup.com`.
- `CRON_SECRET` — без него напоминания по cron не идут. Vercel Cron передает его сам.
- `TG_WEBHOOK_SECRET` — без него бот не привяжет чат. Тот же секрет передать в `setWebhook` как `secret_token`.
- `EMAIL_MODE=test` — только на превью, и ссылки в ответе только для тестовых доменов.

## 4. Проверено, проблем нет

- **Запрет по умолчанию.** Неизвестный маршрут, включая `__proto__` и `constructor`, → 403. Неизвестная роль или тариф → нет прав (`can`).
- **Проверка прав в каждом маршруте.** Все 16 служебных маршрутов: партнер любого тарифа → 403, владелец без ключа → 403, без сессии → 401.
- **Тариф и приостановка в открытой сессии.** Партнер перечитывается при каждом запросе. Понижение тарифа сразу закрывает «Все», чужие карточки, обращения и подарки. Приостановка гасит сессии (`sessVer`), iCal, пуши и вложения.
- **Сетевое представление.** Собирается только через `networkView`. Нет `owner`, `cells`, `relation`, `capitalBasis`, `plan`, `history`, `linkId`, `primary`. Фильтры и поиск работают по уже отфильтрованным строкам. В `demand` нет alias и id. Текст запроса уходит в сеть только из `publicText`, контакты в нем вырезаются.
- **IDOR.** Карточки, заметки, задачи, обращения, вложения (`rq/att` по правам ветки), семейные приглашения: чужой id → 404, данные не меняются.
- **Заметки.** Ключ `crm/note/<автор>/<cid>`. Владельцу Orbiq чужие заметки не видны.
- **Календарь.** Токен 24 байта, в базе только хеш, ротация гасит старую ссылку. В событии нейтральное название и ссылка `/crm/`, без имени клиента.
- **Пуши.** Нейтральный текст без имени клиента и содержания. После приостановки не уходят. Повтор события не дает второго пуша.
- **Токены.** Вход: HMAC, 30 минут, одноразовый. Приглашение партнера — 32 байта. Семья — 32 байта. Код семьи — 6 цифр, 5 попыток, 5 запросов кода в час. Везде в базе хеш. Сравнение за постоянное время.
- **Лимиты.** Вход: 5 в час на почту и на IP. Ключ владельца: 5 за 15 минут. Разбор: 60 в час. Обращения: 30 в сутки.
- **Открытые редиректы.** Все редиректы на фиксированные пути `/crm/…`.
- **XSS.** API отдает JSON с `nosniff`. Интерфейс экранирует данные через `E()`. В имени нельзя `<`, `>`, `=`, `(`.
- **Гонки.** Имя (NX), квота, места, оплата, активация, повтор обращения — CAS на одном документе.
- **Журнал.** Без текстов заметок, импорта, контактов и почты. Текст разбора не пишется никуда.
- **Cookie.** `HttpOnly; Secure; SameSite=Lax; Path=/; Max-Age`. Фиксация сессии невозможна: cookie выдает только сервер, при входе и повышении прав — новая.

## 5. Мелкие замечания без исправления

- Сессия партнера живет 30 дней. Для рабочего кабинета с персональными данными разумно 7–14 дней.
- Два одновременных переименования одной карточки оставляют одно из новых имен занятым навсегда. На безопасность не влияет.
- Почтовые сканеры могут открыть одноразовую ссылку входа раньше человека. Тогда ссылка сгорает, человек запрашивает новую.
- `pf/decide`, `pf/extend`, `pf/final`, `partner/suspend` не проверяют формат `pid`. Это маршруты только владельца, несуществующий id дает 404.
